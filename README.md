# Tabular Foundation Models for Outlier Detection

Evaluation of **Tabular Foundation Models (TFMs)** for outlier detection. The TFMs are benchmarked against baselines, and additional strategies for exploiting **free-text features** are investigated.

**Author:** Florian Veitz — TH Köln, in cooperation with inovex GmbH.

---

## Setup

### Environment
- **Package manager:** [`uv`](https://docs.astral.sh/uv/) — must be installed. `uv sync` sets up Python (pinned in `.python-version`) and all dependencies from `uv.lock` automatically.
- **Hardware:** a CUDA-capable GPU for the TFMs (TabPFN, ConTextTab, AnoLLM, FoMo-0D); this work used an **NVIDIA A40-12C** vGPU. The PyOD baselines and the evaluation (`experiment_summary.ipynb`) also run without a GPU.
- **Internet:** required once to download the model weights from HuggingFace (see [Model weights](#model-weights)).

### Reproduce everything
1. **Clone the repo** and run **`uv sync`**.
2. **Raw data:** download from [Sciebo](https://th-koeln.sciebo.de/s/FJzqqF7RpSr8Hdj/download) into `data/raw/`.
3. **Foundation models & weights:** AnoLLM (`anollm_src/`) and FoMo-0D (`FoMo-0D/`) are vendored in the repo (see [`VENDORED_SOURCES.md`](VENDORED_SOURCES.md)); TabPFN and ConTextTab come via `uv sync`. FoMo-0D additionally needs its checkpoint — see [Model weights](#model-weights).
4. **Run experiment notebook & preprocessing**
5. **Evaluate:** run `experiment_summary.ipynb` to produce `result_tables/` and `diagrams/`.

Preprocessed data is **not** distributed: it is seed-dependent by construction (see [Train/validation/test setup](#trainvalidationtest-setup)) and is regenerated by step 4.

### Model weights
- **Automatic from HuggingFace** (on first run, internet required, **no token / no `.env`**): TabPFN, ConTextTab (`rpt-1-oss`), the Sentence-Transformer `all-mpnet-base-v2`, and the AnoLLM base model.
- **Manual — FoMo-0D only:** the checkpoint is **not** fetched automatically. Download `ckpt.zip` (~32 MB) from HuggingFace [`YuchenShen/FoMo-0D`](https://huggingface.co/YuchenShen/FoMo-0D) into `FoMo-0D/ckpt.zip` (the notebook unpacks it to `FoMo-0D/ckpt/`).
- **PyOD baselines** (iForest, LODA, ECOD, Auto-Encoder) have no pretrained weights — they are trained per run.

## Train/validation/test setup

- **Split:** stratified **50 % train / 20 % validation / 30 % test**, keyed on the stable `row_id`, drawn once per seed in `preprocessing/cleaned.ipynb` and written to `data/splits/split_<dataset>_seed<k>.csv`. Every other notebook reads that file; no notebook splits on its own.
- **Everything is fitted on train only.** This covers the models *and* the preprocessing: median/mode imputation, frequency encoding, constant-column detection, `StandardScaler`, PCA, the fastText model, and the TabPFN embeddings all see training rows exclusively. Categories unseen in train receive frequency 0.
- **Validation is used only for hyperparameter selection** (grid search, AUPRC) and is never fitted on.
- **Test is untouched** and always keeps the original outlier distribution, so AUPRC and AUC-ROC stay interpretable.
- **Three seeds (1, 2, 3)** per model, passed via the `SEED` environment variable. The seed drives both the split and the model initialisation and is logged as the MLflow parameter `seed`, so the reported spread is a genuine measure of variability.

| Group | Models | Training data |
|---|---|---|
| Unsupervised | iForest, LODA, ECOD, Auto-Encoder, TabPFN (unsup.), FoMo-0D, AnoLLM | train split, original distribution, **without** labels |
| Supervised / Enhanced | TabPFN-Enhanced-Embeddings, ConTextTab, TabPFN-classification | train split, **with** labels |

The unsupervised training set contains outliers at their natural rate (4.84 % / 3.93 %) — this is unsupervised outlier detection on a contaminated training set, **not** one-class novelty detection.

## Experiments

Layout: `<dataset>_notebooks/<experiment>/notebook.ipynb`. **MLflow** logs all results into `mlruns` (no database). Logged metrics: **AUPRC**, **AUC-ROC** and runtime; a **classification report** is printed per model.

For score-only models (AnoLLM, TabPFN-unsupervised, FoMo-0D) the classification report uses a threshold at the top-`k` scores, with `k = test size × outlier rate in train` — a rule that uses no test information.

### Experiment 1 — Unsupervised outlier detection

How do TFMs perform in an unsupervised setting?

- **TFMs:** TabPFN (unsupervised), AnoLLM, FoMo-0D
- **Baselines (PyOD):** iForest, Auto-Encoder, LODA, ECOD — grid-searched per seed on the validation split (AUPRC), then refitted on train
- **Data:** `cleaned` for all models. Exception: **AnoLLM** receives **readable raw values** (categories/location/date as strings, rates as numbers, free texts; leakage and ID columns removed), since it serialises each row as text.
- **Score direction:** each method is evaluated with its **native** score orientation (higher = more anomalous); scores are **not** flipped based on the test labels.

### Experiment 2 — Enhanced baseline models

Which free-text representation helps the classical detectors most? The baselines are trained on **7 representations**: `semantic_pca30`, `semantic_pca100`, `fast_text_pca30`, `fast_text_pca100`, `enhanced`, `enhanced_pca30`, and `enhanced_semantic_pca30` (join of `enhanced_pca30` + `semantic_pca30`, built in the notebook itself).

`cleaned` is deliberately absent — it is covered by Experiment 1, and recomputing it here would report two slightly different numbers for the same model/representation pair. Each detector/representation combination gets its own grid search on the validation split.

### Hyperparameter search space (Experiments 1 and 2)

Both experiments use the same exhaustive grid (`sklearn.model_selection.ParameterGrid`, 13 candidates in total). The winner is the candidate with the highest AUPRC on the validation split; it is then refitted on train and evaluated once on test.

| Model | Search space | Candidates |
|---|---|---|
| iForest | `n_estimators ∈ {100, 200}` × `max_features ∈ {0.5, 1.0}` | 4 |
| LODA | `n_bins ∈ {10, 20}` × `n_random_cuts ∈ {100, 200}` | 4 |
| Auto-Encoder | `hidden_neuron_list ∈ {[64,32], [32,16]}` × `epoch_num ∈ {20, 50}` | 4 |
| ECOD | parameter-free | 1 |

`random_state` is set to the current seed wherever the estimator supports it.

**The selection is repeated per seed, and the winners are not stable across seeds.** Of the 48 (dataset × representation × detector) combinations, only 7 pick the same configuration for all three seeds, and across all runs each grid point wins roughly equally often — between 52 % / 48 % (iForest `n_estimators`) and 67 % / 33 % (LODA `n_random_cuts`). The optimum is therefore flat: which candidate wins is largely noise, and the run-to-run spread in test AUPRC (median 11.9 % relative standard deviation across seeds) is dominated by the split rather than by the hyperparameter choice.

For that reason the selected configurations are **not** reported per seed — a "modal winner" at 52 % against 48 % would suggest a stability that does not exist. The reproducible statement is the search space above plus the selection criterion; the concrete winner of each run is logged as MLflow parameters and can be read from `mlruns/`.

### Preliminary experiment — Semantic relevance (SHAP)

SHAP analysis with **SAP ConTextTab** as classifier: it processes numeric features and free texts natively (one column = one feature), so the relevance of each free-text column is directly measurable.

- Context and SHAP background come from the **train split**; the context is balanced 1:4 (120/480) because ConTextTab otherwise sees too few outliers.
- The performance gate before the SHAP analysis runs on the **full test split in its natural distribution**.
- **KernelExplainer** (model-agnostic) yields a mean |SHAP| value per feature.
- Output: per-feature SHAP table plus the numeric-vs-free-text comparison as a **sum and as a mean per feature** — the groups differ in size (40 numeric vs. 4 text columns for Airbnb), so the sum alone is misleading.

### Experiment 3 — TFMs for binary classification

Which model is better for binary classification as outlier detection: **ConTextTab** vs. **TabPFN classification**?

- **Two context variants per model** (logged as MLflow param `context`), both with **exactly 1500 in-context training rows**:
  - `natural`: the training distribution (73 outliers for Fake Jobs, 59 for Airbnb Paris)
  - `balanced_1to4`: 300 outliers / 1200 inliers
  - shared rows for both models → fair comparison
- **Context size is identical in both variants**, so the contrast isolates the composition. Earlier versions compared a 4000-row natural context against a 600-row balanced one, which confounded balancing with context size.
- **Both variants are evaluated on the same, untouched test split in its natural distribution.** Only the context composition varies, so AUPRC stays comparable between the variants and with Experiments 1 and 2.
- TabPFN: numeric features only. ConTextTab: the same numeric features plus the original free texts, processed natively.

### Results (`experiment_summary.ipynb`)
- **Per experiment & dataset:** table with **AUPRC**, **AUC-ROC**, runtime and `n_runs`, as mean ± standard deviation **across the three seeds**, plus bar charts.
- **Preliminary experiment:** SHAP relevance table (per feature, with the spread across seeds) plus bar charts.
- Source: aggregated MLflow runs from `./mlruns`; missing experiments are skipped.


## Limitations

### Methodological
- **Label-guided hyperparameter selection:** the baselines are algorithmically unsupervised — no `fit` ever sees a label — but the hyperparameters are chosen by AUPRC on a labelled validation split. In a strictly unsupervised setting that information would not exist. This favours the baselines over the untuned TFMs.
- **Label leakage in the Enhanced variants (Exp 2):** the TabPFN embeddings are fitted on the label by construction. Fitting on train only removes the test leakage, but the variants remain **semi-supervised** and are not directly comparable to the unsupervised pipelines.
- **Artificial label for Airbnb Paris (ICC):** there is no natural anomaly label; the proxy is defined via `review_score_rating`. Ratings between 3 and 5 are excluded, removing the transition region and making the problem artificially easier. Since ratings are subjective, transferability to real scenarios is limited.
- **The in-context training size in Experiment 3 is capped by the number of outliers, not by the model.** A 1:4 balanced context of *n* rows needs *n*/5 outliers, and the Airbnb training split contains only 360. The largest size feasible on both datasets with some headroom is therefore 1500 rows — well below TabPFN's 4000-row context limit. The experiment consequently reports how the two models behave at 1500 in-context rows, not at their maximum capacity.
- **SHAP ranking uncertainty is not quantified:** the three seeds yield three rankings with a mean and standard deviation, but no bootstrap confidence intervals and no rank-stability measure.
- **One-hot level set (Airbnb)** is determined over all rows. The rarest level has 36 rows, so the probability that it falls entirely outside a 50 % stratified training sample is negligible.
- **fastText residual nondeterminism:** `thread=1` removes the Hogwild nondeterminism, but the internal RNG is fixed at 0 and not exposed by the Python binding. Variation across seeds therefore comes from the differing training corpus.

### Technical (A40-12C vGPU limits)
- **AnoLLM:** batch size = 2 and `max_steps = 1000` (otherwise CUDA OOM / excessive runtime); Airbnb additionally needs gradient checkpointing.
- **TabPFN:** max. 4000 context rows for classification, 9000 for the embedding extraction (attention scales quadratically in the number of samples).
- **Semantic embeddings:** PCA is mandatory — without dimensionality reduction the free-text embeddings produce thousands of features and exceed GPU memory.
